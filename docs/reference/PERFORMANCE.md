# 架构与性能优化

## 运行架构

| 层面 | 已实现的优化 |
|---|---|
| 跨进程 | GUI 和命令行通过本机套接字控制同一个后台录制服务。服务启动独立的 FFmpeg 编码进程；需要原始摄像头视频时，可另起一个编码进程。界面不承担录制或编码，关闭界面后服务可以继续。 |
| 跨进程预览 | 录制服务把最新合成帧写入共享内存，Qt 读取 BGRA。Studio 单独在工作线程为 WebView2 准备 JPEG 预览，忙时跳过旧帧。摄像头监看和画中画复用采集结果。 |
| 进程内线程 | 录制、WASAPI 采音、预览发布、剪辑解码和素材分析各有后台工作。剪辑解码最多排队四帧；音频按设备包增量写入磁盘，长录制无需把全部声音留在内存。 |
| 编码与采集 | 运行时实际探测 NVENC、QSV、AMF，再回退 x264；主视频只编码一次，收尾直接复制视频流并封装音频。桌面采集复用 DXGI 纹理和无新画面的缓存；HDR 色彩转换由 GPU 执行。 |
| 编辑与导出 | 暂停时按需解码所选帧，播放时限制预览分辨率和帧率，避免让编辑预览消耗完整输出的解码资源；字幕识别和神经旁白也调用本地独立工具。 |

多进程隔离界面、录制和编码。同一会话的主视频由一个编码进程写入，声轨在录制结束后封装。摄像头、标注和兼容采集路径会使用 CPU 处理，具体负载随来源和设备变化。

## 2.3.9 本机测量

目标帧率、实际写入帧数、调度补帧和帧位遗漏用于区分文件帧数与采集连续性。`--status` 报告录制服务进程的 CPU 和内存，另外运行的界面、编码和语音进程各有自己的资源占用。本机 NVENC 的短录、长录、实际解码与演示样片指标见 [2.3.9 验收](../validation/VALIDATION-V239.md)。

演示工作台以 2560×1440 像素进行实录和成片导出。抽查固定顶栏区域，界面到实录的结构相似度为 0.9848，实录到成片为 0.9995。此项测量针对同一静态区域和导出设置。

## 历史本机证据

- [2.0 NVENC 验收](../validation/VALIDATION-V2.md)：600 秒录制，完整解码 18,000 帧，4 帧为调度补帧。
- [2.2.1 实时预览验收](../validation/VALIDATION-V221.md)：两组短时画中画场景下，GUI 收到的新帧约为 23.76 和 22.35 fps。旧版约 6 fps 是轮询设计上限，不是同条件实测的基准。
- [2.2.2 HDR 验收](../validation/VALIDATION-V222.md)：实测不同 DPI 的 SDR/HDR 双屏，验证 GPU 色彩转换及实际录制。单次结果受设备和场景影响，不能当作通用速度保证。
