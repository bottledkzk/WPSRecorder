# 设计说明

## 录制链路

```text
主屏幕或区域 ─ DXGI 桌面复制 ─┐
多屏跨区回退 ─ GDI StretchBlt ├─ 光标与点击叠加 ─ BGRA 帧 ─ FFmpeg H.264 ─ MKV 中间文件
指定窗口 ─── PrintWindow ───┘                                        │
麦克风 ─ WASAPI 捕获 ─── QPC 对齐的 48kHz 双声道 float PCM ──────────┤
系统声 ─ WASAPI loopback ─ QPC 对齐的 48kHz 双声道 float PCM ─────────┤
                                                               混音与 AAC ─ 最终容器
```

项目自行实现采集和编排，不调用现成录屏软件源码或一键录屏封装。FFmpeg 接收我们提供的原始画面与音频。选择独立编码进程可隔离编解码器故障，也使依赖部署和进程性能采集直接可查。

## 状态和资源所有权

状态为 idle → starting → recording → finalizing → idle。暂停作为 recording 的附加状态，不创建另一个任务。每个服务只允许一次录制；GUI 和 CLI 通过同一用户本地 IPC 控制同一个任务。工作线程持有采集资源、音频线程和 FFmpeg 进程；停止时先结束采集、回收音频线程，再关闭编码器输入等待封装。

服务使用 QLockFile 防止并发实例，套接字仅允许当前用户访问。启动后台服务显式关闭句柄继承，并将标准流指向空设备，防止 `subprocess.run(capture_output=True)` 等调用方因后台进程保留管道而无法返回。后台服务空闲 60 秒自行退出，也提供 `--service-exit` 结束空闲服务。

GUI 和 CLI 经当前用户的本地套接字发送控制请求；后台服务持有录制任务，FFmpeg 进程负责编码。录制监看用共享内存传帧，缩放由服务中的工作线程处理。一次会话只运行一个录制任务，主视频不按帧拆给多个进程。详见[架构与性能优化](PERFORMANCE.md)。

GUI 的状态轮询和录制服务分离。停止和剪辑导出不阻塞 GUI 主循环。GUI 关闭前若导出尚未结束会提示等待；若仍在录制，会询问后台是否继续。

## 时间与音画同步

首帧送达编码管道后才设置公共 QPC 起点，避免编码器冷启动缩短实际成片。WASAPI 包中的 QPC 时间映射到相同起点，暂停区间从两路音频和视频共同扣除。时间戳缺口填静音、重叠样本裁去；两路 PCM 保持 48kHz 双声道后由 amix 混合，最后以实际视频时长裁切或补齐。

视频按活动时间映射到固定帧率。采集迭代落后时复制最后一帧填补时间轴；`duplicate_frames` 明确报告这类调度补帧，避免将时间轴 FPS 误称为独立画面采样 FPS。DXGI 在桌面没有新内容时复用缓存属于静态画面正常复用，不计入调度补帧。实际播放时长由写入帧数和配置帧率确定。

停止请求记录活动时刻，收尾补齐到该时刻；暂停期间不增长录制时长，系统和麦克风仍及时排空设备缓冲，但暂停包不写入。

## 内存与磁盘

帧写入后等待 QProcess 输出队列排空，保持一帧在途并施加背压，不无限缓存。DXGI 保存一张当前桌面缓存、staging 纹理和缩放画面。音频按设备包增量写入磁盘，不把整段声音放入内存；48kHz、双声道 float 每路约 384 KB/秒。

最终文件写入同一输出目录下的独立工作区，编码完成并封装成功后 rename 到目标文件。既有文件拒绝覆盖，输出锁防止同一路径冲突。成功时删除该次创建的工作区；失败时保留中间视频、PCM 和 encoder.log，便于恢复。部分采集错误会停止采集并尽力保存此前内容，同时返回明确错误。

## 窗口与区域策略

窗口模式每帧重新读取窗口矩形，PrintWindow 获取该窗口内容并缩放到固定输出尺寸；位置和尺寸变化不会改变视频分辨率。窗口最小化或关闭时停止并保存此前内容。部分受保护内容或不实现 PrintWindow 的 GPU 窗口可能无法获取画面，应改为可见区域录制。区域坐标使用物理像素；主屏幕区域优先 DXGI，跨屏区域回退 GDI。2.0.2 的 GUI/CLI 在 Qt 构造前声明 Per-Monitor V2 DPI 感知，消除旧 System-Aware 在混合缩放副屏上的虚拟化；保持 Qt 控件原生坐标与采集一致。虚拟桌面由各显示器原生矩形取并集，不假定显示器位置、尺寸、方向或比例。

2.2.6 在框选层中区分新画选区、移动和拖边角缩放。交互期间限制选区在虚拟桌面内，更新尺寸提示，仅重绘变动区域。选区确认后才写回物理像素矩形；Esc 取消，下次进入恢复上一次确认结果。透明区域保留少量透明度以接收原生鼠标事件。边角缩放与混合 DPI 的实测见 [2.2.6 验收](../validation/VALIDATION-V226.md)。

## 录制监看与工具交互

2.2.1 将预览移至 previewchannel：录制线程只提交隐式共享的最终合成 QImage 与摄像头图像；后台线程最多保留一个待处理帧，最高约30fps缩放至960×540/480×360。Windows当前用户命名映射传递BGRA，不经过GUI逐帧JPEG编解码；约33ms的精确定时器读取最新帧，不等待互斥锁，忙时跳过。协议校验魔数、版本、宽高上限和固定映射长度，停止时清空活动标记及缓存；旧CLI preview JSON仍可请求JPEG，GUI在共享内存不可用时兼容回退。暂停保持最后已录画面并明确标注，独立摄像头悬浮窗仍排除抓屏。显示器友好名只在列表枚举时查询；逐帧坐标枚举避免反复读取EDID/显示配置。

录制预览复用最终合成结果，设备只采集一次。当前DXGI读取后仍有CPU QImage合成与原始帧传编码器，NVENC加速的是编码；它不是OBS的全GPU场景渲染。OBS的Direct3D11/OpenGL图形体系及显示回调见[官方渲染文档](https://docs.obsproject.com/graphics)。本轮借鉴独立预览、复用合成结果和不积压帧的设计，未引入libobs或宣称达到其零拷贝性能。

讲解工具栏是画布拥有的置顶工具窗口，画布 region/mask 减去工具栏矩形，保证即使置顶层次变化，画笔也不能吞掉按钮的鼠标输入。默认操作模式，收起仍保留操作和退出；Esc、F8 与 Ctrl+Alt+Esc 提供退出和唤回路径。颜色/文字子对话框保留自己的 Esc 取消行为。

## 后期处理

裁剪使用起止时间重新编码，避免仅按关键帧切割产生偏移。拆分按给定多个区间导出，后续区间失败时删除本任务已经产生的片段，保留输入和原有输出。合并先将各段缩放并补边为 1280×720、30fps、48kHz 双声道；无音频片段生成等长静音，再使用 concat filter 合并，支持不同分辨率和帧率的文件。

编辑任务使用独立线程和编码进程，生成成功后再发布输出。原始输入不被改写，已有输出拒绝覆盖。主窗口成片播放器使用 Qt Multimedia，提供播放、暂停、定位、音量、倍速和全屏；2.1.0 可视化剪辑的播放链路另见下节。

### 2.1.0 可视化剪辑

单主视频工程保存源路径、时长、尺寸、文件大小、平均帧率、排序的保留区间、分割点、偶数像素裁剪框、逐音轨启用/音量/保留区间及源时间字幕。源视频不修改；全局切除在导出时 ripple 拼接，字幕按保留段求交集再重计时，声音仅自身切除时补静音。JSON 工程恢复前检查源文件元数据匹配。

预览区与时间轴同窗。后台分析生成 12 张缩略图、每音轨 RMS 波形和 AAC 试听代理，缓存由 QTemporaryDir 管理，波形读取采用有界分块。变更来源会取消旧分析并用代数过滤已排队的旧信号。

剪辑视频不依赖 Qt 系统视频 surface：FFmpeg raw BGRA 解码由工作线程持有，最多四帧排队并背压；GUI 消费帧后推进播放头。预览限制 960×540、30fps；暂停拖动用单帧解码并对齐源帧网格。缓存饥饿暂停试听，恢复后按显示位置重同步逐轨 QMediaPlayer 声音代理。预览缩放/限帧不改变原素材或导出的平均帧率（支持 1–120fps）。

导出通过 filter_complex_script 避免长 Windows 命令行：保留段 trim/setpts/concat、显式 fps、crop、各轨静音与音量，字幕按需生成为临时 ASS 烧录或可选字幕流。使用独立工作目录和 QSaveFile/重命名发布，已存在目标拒绝覆盖。任务使用点击导出时的工程快照；关闭忙碌任务被阻止，未保存计划在退出主程序时提供保存选择。

# 2.0 补充

新版本保留单用户本地服务与公共录制时钟。窗口、区域、选定显示器或图片先得到 BGRA 帧，Media Foundation 摄像头（设备可用时）提供最新帧，C++ QPainter 进行画中画及讲解合成，固定遮挡在编码前执行；放大前后均施加遮挡，避免放大镜重新显示被遮挡像素。GUI 覆盖层使用 Windows 窗口捕获排除能力；不支持时拒绝展开工具覆盖层，避免工具与合成画面重复录入。

`scene` IPC 只允许替换画面来源、摄像头样式、鼠标与效果等字段，不能改变输出路径、尺寸、帧率或音轨配置。JSON 场景限制为 50KB、最多 200 个形状和 40 个遮挡区域。预设仅为声明数据，不执行外部代码。

硬件编码采用实际一帧编码探测，显式选择失败向调用方返回原始错误；auto 顺序为 NVENC/QSV/AMF/x264。同一进程缓存探测结果，驱动或 FFmpeg 改变后需要重启服务。主视频只编码一次，最终文件拷贝视频流并添加音轨；系统/麦克风可混音或保留独立轨。额外摄像头视频统一为 640×480 与主视频时间轴对应；补帧同时保留上一主画面对应的原始摄像头帧。2.0.1 的资源统计计入额外摄像头编码进程。

摄像头采用异步 Source Reader 回调，回调只存放结果并通知采集线程；由 MTA 采集线程取样、更新最新画面、取消待完成请求和关闭设备。停止调用方只发出标志并等待采集线程收尾，避免从未初始化 COM 或其他 apartment 的线程调用设备 Shutdown。回调共享状态与外部画面状态分离，关闭后的回调不会访问已销毁的捕获对象。具体设备验收以 [功能清单](../course/FEATURE-STATUS.md) 和本轮证据为准。

预约由常驻服务定时器触发，并通过引擎有效时长自动停止；GUI 退出后服务仍等待已预约任务。服务退出/系统关机不保留预约。字幕任务在独立工作线程转音频并执行本地 whisper-cli，临时目录自动回收，输出采用拒绝覆盖的重命名发布。

## 2.2 控制和语音

recordingwidgets提供无原生owner的置顶浮条，避免主窗口最小化时一起隐藏；主窗口负责销毁，按钮复用原有录制控制。KRRLiveCanvas在实际视频矩形内处理相对位置/缩放，设置框阻塞中间信号后去抖发送scene，不改变输出尺寸。

标注保存最多40个效果快照，橡皮按路径命中删除整笔/图形，不删除隐私遮挡。粗细记录在每个shape的width字段。服务继续在编码前合成，覆盖层保持捕获排除和真实工具输入孔。

speech模块封装SAPI与外部Sherpa-ONNX进程，不将整套录屏软件引入项目。文本通过结构化进程参数传递，不执行shell命令；WAV与视频在同目录独立临时工作区生成，拒绝覆盖后rename发布。旁白按成片时间延迟并混音，超过片尾拒绝，视频流复制避免声音合成再次编码。

自动字幕支持选轨、模型、语言；中文显式模式用Windows NLS转换简体，其他语言保持模型输出。识别、神经合成和剪辑导出支持取消；日志持续排空并限长，避免长任务日志占用无限增长。模型不常驻，生成时启动、结束后释放，换取更低空闲内存而承担冷启动耗时。

## 2.2.2 原生屏幕颜色与预览窗口

DuplicateOutput1协商格式并回退DuplicateOutput，始终检查实际D3D纹理Format；浮点scRGB先用系统SDR白电平归一化，10位HDR PQ进行线性化和Rec.2020→Rec.709变换，SDR保持对应通道顺序。像素着色器输出BGRA8再Map读回，CPU不逐像素运行pow。按纹理真实尺寸/格式重建读回资源；采集失效短时保留最近帧并重连，超时允许兼容回退。Windows颜色/白电平按格式变化或周期刷新，不写系统设置。录制RGB→YUV使用明确的BT.709矩阵、有限范围与sRGB传递标记。此工作不等于全GPU场景合成，摄像头/标注仍使用QImage。

KRRPlaybackSlider用样式实际轨道/滑块尺寸换算点击位置；45ms合并连续移动，释放时提交最终定位。KRRPlayerWindow移动同一视频控件，默认根据当前QScreen.availableGeometry铺满工作区，顶部保留模式切换及×；完全全屏为可选模式，不更改任务栏或系统布局。
