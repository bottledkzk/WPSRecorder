# WPS Recorder 2.3.9 设计说明

WPS Recorder 面向课程讲解、软件演示和操作记录。Windows 接口负责采集，C++17 与 Qt 5 负责本地设备、任务控制、时钟和文件，FFmpeg 负责编码、封装与导出。Studio 的 HTML、CSS 和 JavaScript 随程序部署，由 WebView2 在本机加载。预览、剪辑和模型分析使用各自的处理路径。

## 1. 模块划分

原生模块位于 `src/`，工作台页面、主题和交互位于 `studio/`。`docs/CMakeLists.txt` 和项目根构建入口连接同一套源码。

| 模块 | 代码入口 | 职责 |
| --- | --- | --- |
| 工作台与命令行 | `webstudio`、`webstudiosurface`、`studioworkspace`、`mainwindow`、`climain` | 渲染工作区，管理场景、来源与设备，执行本机命令，提供 Qt 工作台兼容入口 |
| 录制服务 | `controlserver`、`recordingengine`、`recordingclock` | 管理任务和设备，统一音画时钟，控制编码与封装 |
| 采集与合成 | `framecapture`、`desktopcapture`、`windowcapture`、`audiocapture`、`cameracapture`、`compositor` | 采集屏幕、窗口、系统声、麦克风和摄像头，合成画中画与讲解效果 |
| 监看与成片播放 | `previewchannel`、`previewvideo`、`playerwindow` | 向界面传递最新监看画面，播放成片并处理格式兼容 |
| 剪辑与交付 | `webstudioedit`、`editproject`、`editsequence`、`mediaeditor` | 编辑和保存时间轴，重新定位素材，校对字幕、混音、编排多素材和导出成片 |
| 语音与模型服务 | `subtitledialog`、`speech`、`dubbing`、`speechservices` | 录后识别、可选翻译、逐句配音和服务能力检验 |
| 录屏助手与智能剪辑 | `studioassistant`、`assistanthistory`、`recordingassistanttools`、`smartcut`、`sequencesmartcut` | 管理上下文，调用本机工具查找录像、预览设置建议并生成剪辑草稿 |

~~~text
工作台与 CLI ──本机控制消息──> 录制服务
录制服务 ──最新监看画面─────> 共享内存 ──> 工作台
录制服务 ──视频帧───────────> FFmpeg 编码 ──> 中间视频
录制服务 ──对齐后的声音─────> 临时 PCM
中间视频与声音 ──封装───────> 成片 ──> 剪辑与导出
~~~

## 2. 录制链路的设计取舍

### 控制与采集分开

图形界面与命令行共用录制服务，通过本机套接字发送开始、暂停和停止等指令。录制服务持有采集设备和编码子进程，按启动、录制、封装的顺序管理资源。监看线程将最新合成画面写入共享内存，WebView2 的预览帧由单独的后台任务准备，忙时跳过过时帧。录制服务直接向 FFmpeg 提供视频帧。

### 用同一时钟对齐画面与双路声音

首帧送入编码管道后，以 QPC 高精度计时器设定录制起点。WASAPI 采集的系统声和麦克风按同一时间轴对齐。暂停时长从视频和两路声音的有效时长中一并扣除。视频按设定帧率排布，采集落后时复用上一帧，单独记录调度补帧次数。音频按包写入临时 PCM，缺口补静音，重叠部分裁掉。48 kHz 双声道浮点 PCM 每轨每秒约用 384 KB 临时磁盘空间。逐包落盘使长录制的内存用量保持稳定，封装时仍可选择混音或分轨。

### 完成封装后发布成片

录制前可在工作台核对实时画面与混音器电平。录制期间，中间视频、音频和编码日志放在目标目录下的临时工作区。封装成功后，将产物改名为正式成片。采集或编码出错时，界面显示失败阶段，可用数据可从可恢复素材另存。打点按成片时间保存，供回看定位和编辑。

## 3. 剪辑、语音和模型如何衔接

剪辑工程记录素材引用、原片区间及排序、裁剪框、独立音轨、字幕和章节。编辑器用时间映射关联播放头与原片。导出按工程快照拼接片段，并换算声音、字幕与章节在成片中的位置。素材移动后，顺排模块比对文件大小和内容指纹，再更新引用。预览使用有界队列，最终导出读取原素材并可指定码率和字幕模式。

语音处理在停录后执行。whisper.cpp 读取指定音轨，生成带起止时间的字幕。用户可直接为原文配音，也可先做中英翻译。每句音频可以单独试听和重做，确认后对齐并生成一条可剪切的独立音轨。译文、配音与章节沿用源片时间，导出时一起换算。配音可选择本地引擎或外部服务。模型服务按任务封装接口差异，通过能力检验核对工具调用、翻译、视觉输入或音频输出。已保存的密钥交由 Windows 凭据管理器。

录屏助手将一句自然语言转成结构化工具请求。它从本机记录的保存目录、近期录像和标记中查找素材。设置变更先列出原值与建议值，用户确认后应用。

多素材混剪先将保留区间分成彼此重叠的分析窗口。自动档以 4 FPS 初筛，结合字幕、标记和本地提取的声音峰值寻找候选。候选及附近画面再以 8 FPS 复核，局部样本最高为 800×450 像素。这样可以把密集采样用在可能出现短动作的区段。编排时会合并紧邻的动作片段，便于保留起势、动作和结果。草稿附有源片时刻和建议切点，用户可以回看、调整顺序与切点，再应用到工程。

## 4. 问题定位与解决

### 1080p60 录制的写入等待

游戏实录曾出现编码管道写入等待，调度程序频繁用上一帧补齐时间槽。分段测量取帧、读回与合成、像素转换和管道写入后，发现主要时间花在读回后的处理和向编码器写入数据上。HDR 采集路径将适用的裁剪和缩放移到 GPU 读回之前。NVENC 输入从 BGRA 改为 NV12，FFmpeg 的输入、输出和滤镜线程也分别设限。

单张 1080p 帧的管道写入量由 8,294,400 字节降至 3,110,400 字节。修复前后两轮分段计时的采集与合成 P95 分别为 16.79 ms 和 4.81 ms。修复后用街霸 6 实战连续录制 600 秒，写入 36,000 帧，其中调度补帧 370 帧，占 1.03%。1080p30 单独复测写入 3,600 帧，调度补帧为 0。 [录制性能实测](validation/VALIDATION-V228.md#录制性能)

### 成片预览卡住与跨屏后的画面异常

早期播放器尝试恢复停帧时，同步调用 DirectShow 的停止操作，界面线程随解码链一起等待。新版默认使用 Media Foundation。显示层复制所需图像后交还解码缓冲，停帧恢复使用播放定位。关闭时先释放播放器，再销毁显示表面。AVI 和 FLV 的兼容预览在后台准备，优先重封装，按需转码。约 6.5 秒的观测窗口内，联调 MV 和街霸 6 视频分别呈现 195 帧和 390 帧。另用联调 MV 检查了变速、暂停后变速与跨屏移动。 [播放器实测](validation/VALIDATION-V228.md)

### 多素材成片的默认音轨

早期顺排成片的后段声音落在另一条音轨。播放器按默认轨播放，后段听起来像静音。现在顺排导出先生成一条贯穿全片的默认混音，再按需保留独立音轨。某段缺失的分轨用等长静音占位，使各轨与画面对齐。顺排专项用三段街霸 6 素材检查切点、断链重定位、双语字幕与章节，导出时长 12 秒、共 720 帧的 1080p60 成片。 [多素材专项](validation/VALIDATION-V228.md#多素材与智能剪辑)
