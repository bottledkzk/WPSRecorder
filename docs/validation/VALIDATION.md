# 验收结果

环境：Windows 11 x64、本机 MSVC 2022、Qt5、FFmpeg 9.0.2 essentials。应用使用自有 Windows 采集模块，所有成片均为实际桌面或自有动画窗口录制。以下数据来自 `evidence/1.0/acceptance.json` 及附加日志。

## 自动验收

完整脚本 `tests/e2e.py` 共 15 个验收项全部通过，包含：CLI 版本与 idle JSON、非法输入与重叠启动拒绝、捕获 stdout/stderr 时后台启动及时返回、系统音频、麦克风、混音、暂停继续、画面变化、MOV/AVI/FLV/MKV、区域录制、裁剪、拆分、异构文件合并、拒绝覆盖、三次反复启停及 10 分钟主屏录制。MP4 为各主要流程的默认输出。

| 检查 | 实测结果 |

## 10 分钟稳定性

主屏幕连续录制，1280×720、30fps、系统声音。共 120 次性能状态采样：

- 成片时长 602.033333 秒，18,061 帧；ffprobe 完整解码计数与服务返回帧数一致。
- H.264 视频 602.033 秒，AAC 双声道音频 602.033333 秒，轨道时长差约 0.000333 秒。
- 录制及封装无错误，文件为 79,944,334 字节，可正常解码。
- 采样峰值工作集 134.765625 MiB；采样峰值 CPU 6.0126%，以系统逻辑 CPU 数归一化，包含服务和当前视频编码进程。
- 10 次调度补帧，占总帧约 0.055%；没有未报告的时间轴丢失。
- 从后台启动后到停止、音频编码、封装及完整解码核对完成约 678.22 秒。停止后约一分钟用于该机器上的音频编码/文件收尾与验证，GUI 显示正在保存。

上述内存和 CPU 是 5 秒间隔的状态采样峰值，不是系统级连续采样峰值。10 分钟长视频保留在本地验收目录，不放入交付包；交付包只包含 3 分钟以内的真实窗口录制样片。

## GUI 与构建

已通过实际窗口操作检查录制状态、计时、播放器加载、重播、全屏画面、Esc 返回、音量调节和倍速。播放器结束重播时显式回到起点；全屏窗口关闭时恢复内嵌预览，避免视频控件隐藏。区域框选、3 秒倒计时与截图也纳入 GUI 验收记录。

Release、Debug 均成功构建，最终 GUI 修正另有 `build-gui-final.txt` 和 `build-debug-gui-final.txt`。源码启用 /W4；构建日志没有 warning/error。对 AVI 容器显式应用 h264_mp4toannexb 比特流过滤器；所有声明支持的容器均由 ffprobe 实际读取。

运行包附带 Qt、VC 运行库和递归导入的依赖；安装脚本的隔离安装验收结果见 `package-check.json`。未使用另一台洁净 Windows 机器或虚拟机验证，应用本身不依赖 Python、Visual Studio 或开发机 Qt 路径。
